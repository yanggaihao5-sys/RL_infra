### 本批得出的四条结论

1. **同 lr 换 seed = 13.14 个百分点的差**（88.40% vs 75.26%，二者 lr 都是 1e-3，只差 seed）。
   ⇒ 🔴 **单 seed 的 best 覆盖率不能用来比较 lr**。若只跑了 `lr1e3_s2024`，会得出"1e-3 最好"的错误结论。
   **口径收窄**：4 个数字**只能用于"跑通装置"**，不能用于任何 lr 优劣结论——n=1 seed，噪声比效应大。
2. **手册级 2 的假设被"部分证实 + 部分修正"**。原假设逐字："`lr=1e-3` 会让 loss 比 `1e-4` 更快下降但更容易震荡/发散。"
   - ✅ **更快**：对。ep50 时 1e-3 已到 88.40%，而 1e-4 要到 ep275 才到 90.21%。
   - ❌ **更容易震荡/发散**：**未证实**。1e-3 的 best（88.40%）并没比 1e-4（90.21%）差多少，且无失败迹象。
   - ⚠️ `loss` 本身**看不出这件事**：三个 lr 的 loss 都在 0.02–0.19 区间（终点 1e-3=0.1487、1e-4≈0.09 量级）——**loss 不是这个实验的判据，覆盖率才是**。这是级 4 命题在**监督学习之外**的又一次现身。
3. ✅ **（v2 结案）`成功率 0.00%` 不是 bug，也不是口径问题 —— 它就是对的。**
   逐字证据（四份 `train.log` 完全一致）：`覆盖率达成阈值 : 0.90` · `单回合步数上限 : 200` · `ℹ️ run 1/5：覆盖率 80.41% | 步数 200 | 成功 False`。
   ⇒ 最高一组覆盖率 **80.41% < 90%** 阈值 ⇒ 四组全部 `成功=False`；步数**打满 200 上限**。
   **结论**：`成功率` 与 `平均完成步数` 在当前配置下**双双饱和**（恒 0% / 恒 200.0）——`config.py:57` 的阈值 **0.90 高于这张测试图的覆盖上限**，所以这两个字段**没有信息量**。
   **改法（二选一）**：① 阈值从 0.90 下调到分布内（如 0.75）让指标有区分度；② 换判据为「达到覆盖率 X% 所需步数」（连续量，不饱和）。
   ⚠️ **v1 把这条写成"三个数字互相矛盾、成功率字段不可用" —— 那是误判，v2 撤回。**
4. 🔴 **（v2 新增，本批最重要）测试环节是"假重复"：`测试轮数 5` 的有效 n = 1。**
   逐字证据：四份 `train.log` **各出现 2 次** `5 次跑结果完全相同 —— 确定性环境 + 贪心策略的**预期行为**（对比实验环境对齐的代价）；要测泛化请加 --eval-random-maps`。
   ⇒ 固定 `seed=0` 地图 + 确定性贪心策略 ⇒ 5 轮输出**逐字相同**。**这 5 轮不能当重复实验**，算不出方差、给不出置信区间。
   **连带纠正 v1 的归因**：v1 说"best 88.40% → test 70.62% 差 17.78pp 是**选择偏差**"。
   ⚠️ **机制错**（方向对、因果错）。逐字反证：
   - 训练块（`train.log:6-15`）：`随机种子 : 2024` · `初始朝向 (度) : [0, 315]` · 固定障碍物 12 个坐标
   - 测试块（`train.log:420-430`）：`链路标识 | test_mode=madqn | 评估模式 | ... | 地图 固定 seed=0` · `随机种子 : 0` · `初始朝向 (度) : [270, 45]`
   ⇒ **best 与 test 跑的是两张不同的地图**，17.78pp 的主因是**换图（域偏移）**，选择偏差最多是次要项，本批数据**无法区分**二者。
   **下一个动作**：`--eval-random-maps`（`config.py:56`）跑多张随机图，才有资格谈泛化与方差。

## 三补 · 2000 回合批次（`rli-2k-g` / 评测 `rli-2kev-g`，2026-10-06）

**为什么跑**：300 回合那批（§一）已证明 n=1 seed 的噪声比效应大 ⇒ 必须加长到 2000 回合才有资格谈 lr。

| run | lr | seed | 训练最优（自我报告） | 独立测试覆盖率 |
|---|---|---|---|---|
| `lr2k_5e4_s2024` | 5e-4 | 2024 | 90.46% @ep1150 | **88.40%** |
| `lr2k_5e4_s7` | 5e-4 | 7 | 90.46% @ep1100 | 81.44% |
| `lr2k_5e4_s13` | 5e-4 | 13 | 90.46% @ep800 | 76.55% |
| `lr2k_1e4_s2024` | 1e-4 | 2024 | 90.21% @ep800 | 76.29% |
| `lr2k_1e3_s2024` | 1e-3 | 2024 | 90.46% @ep225 | 55.15% |
| `lr2k_5e4_rand` | 5e-4 | 2024 | 90.46% @ep250 | 51.29% |

**三条结论（都带数字）**：
1. 🔴 **训练指标在 2000 回合上完全饱和、失去分辨力**：6 个 run 的「最优覆盖」全部落在 **90.21~90.46%（跨度 0.25pp）**，**无论 lr、seed、是否用随机地图**。300 回合时同一指标还有 84.28~90.21%（跨度 5.9pp）。
   ⇒ **加长训练把训练指标"跑平"了，判据必须换成独立测试。**
2. 🔴 **独立测试上，seed 效应 > lr 效应**：
   - seed 效应（固定 lr=5e-4）：**88.40 / 81.44 / 76.55 ⇒ 31.85pp 的跨度**
   - lr 效应（固定 seed=2024）：**88.40 / 76.29 / 55.15 ⇒ 33.25pp**，但**非单调**（1e-4 > 1e-3 却 < 5e-4）
   - ⇒ **单次单图评测不能用来选超参**；本批仍是 **n=1 地图**，结论只能到"排序在某一张固定图上成立"。
3. ✅ **泛化对照给出预期方向**：`lr2k_5e4_rand`（训练期贪心评估就换图）独立测试 **51.29%**，比同配置固定地图的 **88.40%** 低 **37.11pp**。
   ⚠️ 但**这个比较不干净**：两者的差别不只是"评估换不换图"，训练期评估口径不同也会影响 best 的选择。**要干净地测泛化，得让两个 run 用同一套评估、只在最终测试时换图。**

**对照 300 回合的教训**：300 回合时 `lr2k` 这批的对应 run 测试为 70.62/80.41/77.06（§一），2000 回合后变成 55.15/88.40/76.29 —— **排序既不稳定、数值也不单调**。所以"加长训练"**没有**让 lr 的效应变清晰，**反而说明真正的方差来源是地图**。

## 三补2 · A 任务：多地图评测（`rli-maps-g`，每模型 20 张随机图，2026-10-06）

**为什么做**：上面所有结论都建在 **n=1 地图**上。本任务把每个模型在 **20 张随机地图**上重评，
给出 **均值 ± 标准差**，回答"单图排序能不能推广"。

**方法**：`scripts/eval_runs.sh --maps 20 --random-maps`（10 个模型 / 一个作业顺序跑）；
标准差由 `runs/<name>/test_path_plots_en/*.json` 的逐图 `coverage` 聚合
（`scripts/aggregate_eval.sh 20 <run...>`）—— 远端 trainer 版本的汇总行还没打印 std。

| `lr1e3_s7` | 300 | 1e-3 | 7 | 62.63% | 64.87% | 9.44 | 52.06 | 82.99 |

🔴 **本批最重要的四条（修正了上面几节的口径）**：

1. **单图排序不可推广 —— lr 效应从"33pp"缩到"17.6pp"，但不能说是噪声。**
   - 单图（seed=2024）：1e-3 **55.15** / 1e-4 **76.29** / 5e-4 **88.40** ⇒ 跨度 **33.25pp**，像强效应；
   - 20 图均值：1e-3 **57.44** / 1e-4 **69.46** / 5e-4 **75.08** ⇒ 跨度 **17.64pp**（v8 重算；原写 7.64pp 无法复现），
     而**组内图间 std** 是 **8.38~17.25pp**，**均值的标准误 SEM = std/√20 ≈ 1.9~3.9pp**。
   ⇒ **口径修正（v8）**：拿 std 当均值误差是错的（std 是图间散布，不是均值误差）。按 SEM 看，17.64pp **超出**地图采样误差，
   不能说"基本是单图噪声制造的假象"；**但每个配置只训 1 个 seed**（同 lr 三个 seed 的均值跨度 5.22pp），
   所以结论只能到"5e-4 > 1e-3 是工作假设"，**幅度不可引用**。
   ⚠️ v7 原文"7.64pp 落在 ±std 之内 ⇒ 是噪声" 已失效，见 `docs/BENCHMARK.md` §5 与 §6。
2. **单图测量本身的噪声就是 ±8~17pp**（各 run 组内 std 8.38~17.25pp）。
   ⇒ 任何**单图**数字都必须带这个量级的误差棒才诚实。
3. **seed 的"31.85pp 效应"同样缩到 5.22pp**（5e-4 组：75.08 / 70.35 / 69.86）。
   ⇒ 之前的"seed 效应 31.85pp"是**单图噪声被投到 seed 维度上**，不是 seed 真的差那么多。
4. **300 → 2000 回合几乎没有泛化收益**（同图序列、同 seed 2024）：
   | lr | 300 回合 | 2000 回合 | 差 |
   |---|---|---|---|
   | 1e-3 | 70.39% | 57.44% | **−12.95pp（更差）** |
   | 1e-4 | 74.16% | 69.46% | −4.70pp |
   | 5e-4 | 71.22% | **75.08%** | +3.86pp |
   ⇒ **多跑 6.7 倍回合，只换来 −12.95 / −4.70 / +3.86pp**；1e-3 反而明显变差。
   **"训练更久 = 更好"在本任务上不成立。**

**方法论价值**：本任务把 §三补 的结论**从"某张图上的排序"降级为"噪声"**，
正是 §一 第 4 条（"测试环节是假重复，有效 n=1"）的直接兑现。
**从此本项目凡报泛化数字，必须 ≥20 图并带 std。**

## 三补5 · A 阶段：推理内核（D1 分页 KV + D2 连续批，2026-10-24，本机 CPU）

**与前三批的关系**：本批是「DS 准备」A 阶段落进 infra 仓的第一批实测（手册见 `UAV-area-search-DQN-opt/docs/DS准备/`）。

| 表 | 产物 | 数据/产物 | 结论（带数字） |
|---|---|---|---|
| 1 · 内部碎片率 | `kernel/bench_internal_frag.py` | `runs/a1_internal_frag/frag.csv` | 修正式 `w/(mean_len+w)` 在 b=8/16/32/64 × 3 分布共 **12 格全部 Δ<2pt（最坏 0.0036）**；手册原式 `(b−1)/(2·mean_len)` **3/12 格破闸**（全在 b=64，最坏 0.0358）。另有 20 格 (b, mean_len) 探针网格，原式破 6 格、最坏 0.3530 —— **两处网格不同，别混用** |
| 2 · 前缀共享收益 | `kernel/bench_prefix_share.py` | `runs/a1_prefix_share/prefix_share.csv` | 省块数 = **(N−1)×⌈p/b⌉**，6/6 格逐字吻合；省下比例 0.600（p=128,N=10）→ 0.922（p=1024,N=50） |
| 3 · 外部碎片率 | `kernel/bench_external_frag.py` | `runs/a1_external_frag/external_frag.csv` | 固定块分页外碎**恒 0.0000**（结构断言实测成立）；变块首次适配 0.3962（76% 占用）→ **0.8821**（87% 占用），最大可接纳/空闲最低 **0.1179** |
| 4 · static vs continuous | `kernel/bench_batching.py` | `runs/a2_batching/{batching,boundary}.csv` | 工作量比：等长 **1.00×**、高方差 **1.49×**、重尾 **1.89×**；边界 **CV<0.10 时有收益<1.02 倍，CV≥0.50 才达 1.5×** |

**四条结论**：

1. 🔴 **手册的闭式公式本身是错的**，且这次是**实测抓到**而非推理：原式把分母写成「逻辑长度」，
   正确分母是「分配容量」⇒ `w/(mean_len+w)`。原式只在 `mean_len/b ≥ 5` 时可用，
   b=64 时高估 **3.1 个百分点**。12 格里原式破闸 6 格、修正式破闸 0 格。
   **口径收窄**：`selfcheck_kv.py` ⑦ 那个历史 `Δ=0.0026` 是 b=16（比值≈10）的**单点巧合**，不能当"公式已验证"。
2. ✅ **分页用内部碎片买掉了外部碎片**：分页外碎结构上恒 0（块不要求连续 ⇒ 任意 ≤ 空闲槽位的请求都拼得出），
   代价全记在内碎 `w/(m_len+w)` 上 ⇒ **块大小 b 就是这两类碎片的交换旋钮**。
   实测对照：87~90% 占用时变块外碎 0.88、拒绝率是分页的 **1.7~6.9 倍**。
3. ⚠️ **连续批的收益完全是「长度方差的函数」**，不是普适加速：等长档工作量比 **1.00×**（零收益，白付调度复杂度），
   重尾档 **1.89×**。判据边界：**CV<0.10 别上连续批；CV≥0.50 才够手册的 1.5×**。
4. ⚠️ **判读必须用确定性量**：wall-clock 加速比在 CPU 上噪声 ±0.12（零方差对照实测 SD），
   同一零效应情形跨次运行给出过 0.96/1.00/1.09 三个值。本批首跑就用 wall-clock 误判过「等长档有收益」。
   **改用「工作量比 =(tokens+空转槽位) 之比」后判定稳定且可迁移。**

**复现（一条命令，7 项逐个 PASS/FAIL）**：

## 三补6 · B 阶段：训推一体 overlap（2026-10-24/25，高算 GPU，三轮）

**与 A 阶段的关系**：A（推理内核，CPU）已冻结；本批是 B2 的**第一组 GPU 数字**。
代码在 `traintest/`，数字在 `kernel/BENCH.md` 表 5，产物在 `runs/b_overlap_gpu/`。

| 轮 | 作业名 | 设备 · 队列 | 唯一变量 | 结论（带数字） |
|---|---|---|---|---|
| ① | `infr-ovl-g` | A800 **MIG 1g.10gb** · `gpu` | 无预热 | ❌ **废数**：1.843× ± 1.812（MDE 2.093）判不可辨识 —— 预热伪影 |
| ② | `infr-ovl2-g` | **A40 44.42GB 整卡** · `nonmig` | 预热 + 3 rep + 60 步 | **0.933× ± 0.005**（MDE 0.006）⇒ 可辨识：overlap **慢 7.2%** |
| ③ | `infr-cpu3-g` | **A40 整卡** · `nonmig` | 扫 rollout 非 GPU 段 0→80 ms | 0.909~1.013（全程 1±2%）⇒ **加 CPU 段也救不回来** |

**四条结论**：

1. 🔴 **第一轮是废数，必须点出来**：seed 0 的 sync 2.200 s vs 同档 seed 1/2 的 0.352/0.346 s —— 慢 **6.3 倍**。
   那不是重叠效应，是 **CUDA 初始化 + cuDNN autotune 全压在第一档头上**。SD 被抬到 1.812。
   **口径收窄**：不带预热的加速比**一律不入账**；预热本身 11.75 s，比正式测量 1.8 s 还大。
2. ✅ **修正后 SD 从 1.812 掉到 0.005**（预热不计时 + 每档 3 rep 取中位 + steps 20→60 + max_new_tokens 16→32）。
   加速比 **0.933× ± 0.005，MDE 0.006 ⇒ 可辨识**：overlap 慢 1.072×。
3. ✅ **B2 三个数全拿到**：加速比（见上）· **GPU 利用率 98.1/98.2/100.0**（A40 整卡；MIG 上为 `—`，不猜）·
   三段占比 rollout **0.834** / 权重同步 **0.025** / 训练 **0.141** ⇒ **rollout ≫60%，优化推理引擎才有杠杆**；
   权重同步只占 2.5%（每次 1139.2 KiB，59 次共 65.64 MiB）⇒ **不是瓶颈，不用优化它**。
4. 🔴 **机制结论（比数字更重要）**：**单卡上 overlap 只能藏 CPU 段、藏不掉 GPU 段** ——
   生成与训练排在同一块 GPU，串行化由**设备**决定而不是线程。
   给 rollout 加 0~80 ms 的 CPU 段做反证，加速比全程仍在 1±2%（0 ms 处最差 0.909×）⇒
   **单卡 overlap 的理论上限就是 ≈1.0**，再叠线程/握手开销就略小于 1。
   要让它真为正，必须**推/训分离到不同设备**（rollout 独占另一张卡/另一台机器）—— **未做**。

**复现**：

```bash
python traintest/bench_overlap.py --device cpu --seeds 3   # 本机：只验结构
# GPU：bash hpc/submit_b_overlap_nm.sh   （nonmig 整卡，锁 a40gpu01）

```

**诚实短板**：结论建立在 `TinyPolicy`（d=128/2 层/vocab 64）上 —— 量的是**结构**，不是大模型吞吐。
"单卡 overlap 上限 ≈1.0"这条机制可迁移，但**具体百分比不可外推**到 7B 级推理。
