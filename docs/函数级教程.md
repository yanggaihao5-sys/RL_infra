### 和你自己写的 MADQN 脚本对照（全篇反复引用）

| 你自己写的 | 这套骨架里的位置 | 差别一句话 |
|---|---|---|
| `env.step()` 里 `reward += ...` 一堆 if | `madqn_envs.MADroneSearchEnv.step()` | 奖励**拆成带名字的分量**回传，不再只累加成一个数 |
| 主循环里 `print(f"ep {ep} R {R}")` | `rlinfra/logger.TrainLogger.ep_line()` | 格式**只在一处定义**，业务代码不拼字符串 |
| `torch.save(net.state_dict(), "best.pth")` | `RunPaths.best_model()` + `MADQNCTDEAgent.save()` | 路径由「一个名字」派生，模型里还塞了元信息 |
| 主循环里一边采样一边 `train()` | `RolloutActorThread` + 主循环 | 采样在**后台线程**，learner 只管学 |
| `for i in range(episodes): env.step(); buffer.push()` | 同上 | 回合结束信号通过**队列**回传，不共享可变状态 |

## 1. 全局调用图（先看清骨架，再看零件）

### 1.1 启动树

```
python main.py --name X --episodes N
└── main.main()                                     main.py:L101
    ├── build_config(argv)                          main.py:L35
    │   └── Config() / cfg._derive() / cfg.validate()   config.py
    ├── RunPaths.from_config(cfg).ensure()          paths.py:L30 / L38
    ├── TrainLogger(paths.log, algo=...)            logger.py:L24
    └── MODES[cfg.mode](cfg, paths, logger)
        ├── "train" → run_train  → algos.madqn.train_madqn_ctde()   trainer.py:L189
        ├── "test"  → run_test   → evaluate_madqn()                 trainer.py:L345
        └── "smoke" → run_smoke  → 压小参数后同样走 train_madqn_ctde()
```

`MODES` 是**阶段**维度的 dispatch（`main.py:L97`）；**链路**维度的 dispatch 在
`rlinfra.registry.get_algo()`（`registry.py:L68`）—— 二维分离，见 §7.1。

### 1.3 训练主循环一轮的调用树（主线程）

```
train_madqn_ctde()                              trainer.py:L189

├── stats_q.get()                               ← 阻塞等 actor 交回一个回合

├── agent.learn(batch)        ← with weight_lock  agent.py:L74   ← 唯一的梯度更新点
│   └── online.copy_to(target)（每 200 步硬更新）  networks.py:L38
├── logger.ep_line(...)                          logger.py:L75
├── logger.train_line / reward_line              logger.py:L82 / L88   每 print_interval 回合
```

**记住这张图中最关键的三个「跨边界」动作**：
1. `stats_q`（actor → learner，回传回合统计）
2. `weight_lock`（保护 `online.copy_to(rollout)` 与 `learn()` 不打架）
3. `_sync_request`（learner → actor，单向同步权重）

## 2. `main.py`（5 个函数，124 行）

### `build_config(argv)` L35
**职责**：CLI 参数 → `Config` 对象（只覆盖用户显式给了的参数）。
**关键行**：`for f in fields(Config)` 遍历 dataclass 字段，`if getattr(args, f.name) is not None` ——
这就是为什么 CLI 里**没写的参数不会被 None 覆盖掉**。
**它调用**：`Config()` → `cfg._derive()` → `cfg.validate()`。
**被调用**：`main()`。
**⚠️ 坑**：`_derive()` 必须在这里显式调一次 —— 因为 `setattr` 改了参数不会自动重算派生量
（`obs_dim` 就是派生的）。`to_dict()/print_config` 用的是 dataclass 字段反射，所以加字段不用改这里。
**返回**：`(cfg, args)` 元组 —— 注意 `print_config` 是 argparse 的字段、不是 `Config` 的字段，
所以不能挂在 cfg 上（本项目第一版就这么错过，报 `AttributeError`）。

### `run_smoke(cfg, paths, logger)` L71
**职责**：把参数压到最小，跑通一遍全流程（冒烟）。
**关键行**：`cfg.parallel = False` —— **冒烟永远走单进程降级路径**。
**它调用**：`get_algo(cfg.test_mode).train` → `train_madqn_ctde`。
**对照**：相当于你写完新 reward 后，先跑 `--episodes 2` 看看会不会崩。

### `run_train(cfg, paths, logger)` L88
**职责**：一行 —— 从 registry 取链路，调它的训练函数。**这里是「链路维度」的唯一入口。**

### `run_test(cfg, paths, logger)` L92
**职责**：调 `evaluate_madqn`。
**⚠️ 注意**：这里**函数内 import**（`from algos.madqn.madqn_trainer import evaluate_madqn`），
不是偷懒 —— 是为了让 `--mode train` 不必加载评估依赖。小项目里这不是必需的，属于留有余量。

### `main(argv)` L101
**职责**：组装（配置 → 路径 → 日志 → dispatch），并把异常交给 `finally` 收尾。
**它调用**：`build_config` / `RunPaths.from_config` / `TrainLogger` / `MODES[...]`。
**⚠️ 坑**：整个文件**模块级无副作用**，所有动作都在 `main()` 里并在
`if __name__ == "__main__":` 下调用 —— 这是 `multiprocessing` spawn 的硬要求
（子进程会重新 import 本模块，模块级一旦有动作就会被执行两次）。

## 3. `config.py`（唯一的配置源）

### `Config` 字段分组（看代码时按组读，别逐行啃）

| 分组 | 字段 | 关键点 |
|---|---|---|
| ① 命名与产物 | `name`, `runs_root` | **唯一命名源**：换实验只改 `name` |
| ② 链路与阶段 | `test_mode`, `mode` | 对应二维 dispatch |
| ③ 全局训练 | `agent_num`, `grid_size`, `episodes`, `seed`, `device`, `parallel`, `env_count`, `deterministic` | 与算法无关的都在这组 |
| ④ MADQN 链路 | `MADQN_*` 14 个 | **前缀即作用域**：看到 `MADQN_` 就知道只影响这条链路 |
| ⑤ 奖励分量 | `R_*` 11 个 | **每个分量一处定义**，环境里不许再出现魔法数字 |
| 派生量 | `obs_dim`, `n_actions`, `milestones`, `run_root`, `eps_decay_episodes` | **只读**，由 `_derive()` 算出来 |

### `__post_init__()` L78
**职责**：dataclass 构造完成后自动调 `_derive()`。
**对照**：相当于你 `__init__` 末尾调一次 `self._build_net()` —— 保证「对象一出生，派生量就是对的」。

### `_derive()` L81
**职责**：算所有派生量。**核心一行**：
```python
side = 2 * self.MADQN_patch + 1
self.obs_dim = side * side * 2 + 4      # 已访问 patch + 障碍 patch + (行,列) + 覆盖率 + 邻域密度
```
**被调用**：`__post_init__`、`build_config`（CLI 改参后）、`smoke_test.t_end2end`。
**⚠️ 坑**：自己写脚本 `Config(...)` 后再 `setattr` 改参数，**必须手动再调一次 `_derive()`**，
否则 `obs_dim` 会和环境对不上（冒烟自检第①项就是防这个）。

### `derived_summary()` L91
**职责**：把派生量变成几行字符串，打进日志的「派生量自证」块。
**为什么存在**：规范 §8.4 的真实事故 —— `episodes` 5000→1000 让覆盖率 92%→8.7%，
因为**探索衰减终点与步数上限都是按 `episodes` 比例算的**。派生量打出来，这种「看着正常的致命值」才拦得住。

### `validate()` L102
**职责**：启动即断言。挑几条体会一下「拦什么」：
```python
assert self.MADQN_random_episodes < self.episodes   # 否则全程随机、根本不学习
assert self.init_max_train_steps >= self.grid_size  # 否则物理上不可能覆盖完
assert self.eps_decay_episodes > 0
```
**被调用**：`build_config`、`smoke_test`。
**对照**：你自己写脚本时这些值是「拍脑袋填、跑完才发现不对」，这里是**开跑前 0.1 秒就报错**。

### `to_dict()` L122
**职责**：dataclass 反射成 dict，用于 `--print-config` 和存进模型元信息。
**被调用**：`main.main`、`train_madqn_ctde`（存 best 模型时把整份配置一起存进去 → 复现实验的凭据）。

## 4. `rlinfra/`（与算法无关的公共基座）

> 这一层的铁律：**不许出现任何具体算法的词**。出现 `madqn` 就说明放错地方了。

### 4.1 `logger.py` — 日志契约（18 个方法，但只有 3 个需要细看）

**为什么要有这一层**：日志不是给人读的，是**给脚本读的**。
诊断脚本 `utils/analyze_training_log.py` 靠**行前缀正则**解析；只要前缀或字段顺序漂了，
它**不报错、只是静默少解析**。所以格式必须只有一处定义。

#### `emit(line)` L34 —— 唯一真正输出的地方
```python
if self.echo: print(line, flush=True)
if self._fh:  self._fh.write(line + "\n"); self._fh.flush()
```
**它被谁调用**：下面 17 个方法**全部**调它。
**关键设计**：`flush()` —— HPC 作业被 kill 时，没 flush 的日志就丢了；
`flush` 让你能随时 `tail output.<jobid>` 看进度。

#### `__init__(log_path, algo, echo)` L24 / `close()` L41 / `__enter__`/`__exit__` L46/L49
**职责**：同时写 stdout（HPC 的 `output.<jobid>`）和文件（`runs/<name>/train.log`）；
支持 `with TrainLogger(...) as lg:`。

#### 其余方法的契约（看格式就知道诊断脚本为什么能解析）

| 方法 | 行的样子 | 诊断脚本靠它拿 |
|---|---|---|
| `identity(chain, desc)` L53 | `链路标识 \| test_mode=madqn \| ...` | 防「跑错链路」（规范 §8.2 孪生符号事故） |
| `env_banner(algo, items)` L57 | `环境配置一览（本次训练）[MADQN]` + 缩进键值 | 网格/智能体/起点/障碍/阈值（**对比实验前先对齐**） |
| `derived(lines)` L63 | `派生量自证` 块 | — |
| `overview(...)` L69 | `运行设备：cuda \| 地图平均总奖励：... \| 总轮次=2000` | 设备、总轮次、理论最大奖励 |
| `ep_line(...)` L75 | `EP \| ep: 1 \| R: 232.2 \| cov:64.8% \| steps:357 \| loss:.. \| curQ:.. \| td:..` | **趋势主料** |
| `train_line(...)` L82 | `TRAIN-MADQN \| ep: 10 \| loss:.. \| curQ:.. \| tgtQ:.. \| eps:.. \| td:..` | loss/Q/ε 收敛 |
| `reward_line(comps)` L88 | `REWARD(每智能体每步均值) \| name:+0.03 name:-0.05 ...` | **奖励函数诊断的唯一入口** |
| `best_line(...)` L94 | `✅ 已更新 MADQN 最优模型（覆盖保存）\| 回合：250 \| ...` | 最优模型落在第几回合 |

| `test_line(...)` L102 | `测试汇总 \| 全局平均覆盖率：X% \| 成功率：Y% \| 平均完成步数：Z` | 测试汇总 |

**必须**跑 `utils/smoke_test.py` 第⑦项（它拿真 logger 造日志、再用诊断脚本解析、逐字段断言）。

### 4.2 `paths.py` — 产物路径（12 个成员）

**唯一命名源**：`name` → `runs/<name>/`。**函数内禁止硬编码输出路径。**

| 成员 | 作用 | 谁调用 |
|---|---|---|
| `from_config(cfg)` L30 | 工厂：`cls(name=cfg.name, runs_root=cfg.runs_root)` | `main.main`、`smoke_test` |
| `root` L35 | `runs/<name>` 绝对路径 | 各处 |
| `ensure()` L38 | 建目录，返回 self（链式） | `main.main` |
| `child(sub)` L43 | **二级目录的唯一入口**（多模块复用时传同一个 sub，不各自嵌套） | `test_plot_dir` |
| `log` L51 | `<root>/train.log` | `main.main` |
| `best_model(algo)` L54 | `<algo>_best.pth`（**覆盖保存**） | `train`/`eval` |
| `pretrain_model(algo)` L57 | `<algo>_pretrain.pth` | ⚠️ **当前无人调用**（本项目没有 BC 预训练） |
| `final_model(algo, n)` L60 | `n<=0` → `<algo>_final.pth`；否则 `_final_<n>.pth` | 内部 |
| `next_final_model(algo)` L66 | **已有最大序号 + 1** | `train` 两处 |
| `figure(algo, lang)` L79 | `<algo>_training_metrics_{lang}.png` | ⚠️ **当前无人调用**（见 §7.3 欠债） |
| `test_plot_dir(lang)` L82 | `child("test_path_plots_en")` | `_dump_test_artifacts` |
| `prune_final_models(algo, keep)` L86 | 只保留最近 `keep` 个 final，返回被删列表 | `trainer._prune` |

**🔴 `next_final_model` 为什么必须是 `max+1` 而不是「第一个空号」**（L66 的注释值得读三遍）：
清理删掉 `final_1` 后空号又变成 1 → 重新写 `final_1` → 而它按序号是最小的 → **下一轮就被当最旧的删掉**。
实测：日志里「保存完成 final_1」和「清理 final_1」成对刷屏，**最新存档全部丢失**。

**🔴 `prune_final_models` 的三条边界**：只在 `self.root` 内（不递归）、只匹配
`^<algo>_final_(\d+)\.pth$`、`keep<=0` 不清理。删文件的逻辑**必须**有独立自检（`smoke_test` 第⑨项）。

### 4.3 `metrics.py` — `ResourceMeter`（7 个成员）

`start()` L29 / `stop()` L37 / `wall_sec` L43 / `cpu_sec` L47 / `mem_mb` L51 / `stamps()` L61。

**注意两个不同口径**：
- **墙钟** = `time.perf_counter()` 差值 → 你**等**了多久（含排队、含 sleep）；
- **CPU 核时** = `time.process_time()` 差值 → 全部线程**加总**的 CPU 时间。
  本项目实测：墙钟 47s，CPU 核时 484s（torch 多线程 + actor 线程）—— **两个数差 10 倍是正常的**。
- `mem_mb`：Linux 用 `resource.getrusage().ru_maxrss`（单位 KB），Windows 退到 `tracemalloc` 峰值。

### 4.4 `registry.py` — 链路注册表

- `AlgoSpec` L17：一条链路的「零件清单 + 类名」。**类名是字符串**，通过 `_load()` L29 懒加载
  （避免 `registry` 与 `algos` 循环 import）。
- `register(spec)` L63 / `get_algo(chain)` L68 / `registered()` L74。
- 文件末尾 `register(AlgoSpec(chain="madqn", ...))` 就是**唯一的链路登记处**。

**为什么要它**（对照你熟悉的做法）：很多项目用
「`if test_mode == "expert": MADroneSearchEnv = ExpertMADroneSearchEnv`」这种**类重绑定**做切换，
代价是 **import 成功、跑完不报错、却跑错链路**（UAV 项目的真实事故）。
注册表是**显式**的：取不到的链路直接 `KeyError`，名字写错直接报「registry 与 algos 不一致」。

## 5. `algos/madqn/`（一条链路 = 一个包 = 六件套）

### 5.1 `madqn_envs.py` — `MADroneSearchEnv`（**唯一放领域知识的地方**）

#### `__init__(cfg, seed, max_steps)` L28
**职责**：建地图 + 存超参。地图要素**全部由 seed 决定**（起点 / 障碍 / 目标点 / 初始朝向），
存下来供 `snapshot()` 打印。
**关键行**：
```python
rng = np.random.default_rng(self.seed)
self.obstacles = self._sample_cells(rng, cfg.obstacle_num, avoid=())
self.targets   = self._sample_cells(rng, cfg.target_num, avoid=tuple(map(tuple, self.obstacles)))
self.starts    = self._sample_starts(rng, self.agent_num, avoid=tuple(map(tuple, self.obstacles)))
self.free_cells = self.H * self.W - len(self.obstacles)     # 覆盖率的分母
```
**和你写法的差别**：你自己的环境通常 `np.random.seed()` 后就 `random.randint` 撒点，
**每轮 reset 位置都变**。这里**刻意做成确定性** —— 见 `reset()`。

#### `_sample_cells(rng, n, avoid)` L52 / `_sample_starts(rng, n, avoid)` L61
**职责**：撒点，避开 `avoid`，且互不重复。
**⚠️ 坑**：`_sample_starts` 有 `guard < 10000` 兜底 —— 地图太小放不下 N 个起点时，
没有兜底就会**死循环**（不是报错，是卡住）。断言信息是「地图太小，放不下这么多智能体起点」。

#### `reset()` L75
**职责**：清空 `visited`、位置回起点、计数归零。**返回** `List[np.ndarray]`，长度 N，每个 `(F,)`。
**关键行**：
```python
for r, c in self.pos: self.visited[r, c] = 1     # 起点直接算已覆盖
```
**为什么环境要确定性**：这样两次跑出不同结果时，你可以**直接断言「差异来自算法，不是环境」**。
代价：贪心策略下多次评估结果完全相同（要测泛化用 `--eval-random-maps`）。

#### ★ `step(actions)` L89 —— **全项目最重要的 40 行**
**签名契约**：`actions` 形状 `(N,)`；返回 `(obs: List[(F,)]×N, rewards: List[float]×N, done: bool, info: dict)`。
**三段结构**（读的时候按段读）：

```python
# ① 移动（撞障碍：惩罚 + 原地不动）
for i, a in enumerate(actions):
    dr, dc = _MOVES[a]                              # _MOVES 是模块级 9 个方向的元组
    r = clip(pos[0]+dr); c = clip(pos[1]+dc)
    if self.obstacle_mask[r, c]:
        _acc(i, "obstacle_penalty", cfg.R_obstacle); continue
    self.pos[i] = [r, c]; self.headings[i] = self._heading_of(dr, dc, self.headings[i])

# ② 覆盖判定 —— 行为发生的同一时刻，把奖励拆成带名字的分量
for i, (r, c) in enumerate(self.pos):
    if self.visited[r, c] == 1:
        self.stagnant[i] += 1
        _acc(i, "repeat_penalty", cfg.R_repeat)
    else:
        self.visited[r, c] = 1; self.stagnant[i] = 0; new_cells += 1
        _acc(i, "new_cell_base", cfg.R_new_cell)
        if (r, c) in self._target_set: _acc(i, "target_bonus", cfg.R_target_bonus)
    if occupied.get((r, c)) != i: _acc(i, "collision_penalty", cfg.R_collision)

# ③ 全局形状项：每步代价 / 停滞惩罚 / 里程碑
for i in range(N):
    _acc(i, "step_penalty", cfg.R_step)
    if self.stagnant[i] >= cfg.R_stagnation_window: _acc(i, "stagnation_penalty", cfg.R_stagnation)
for m, hit in self.hit_milestone.items():
    if not hit and cov_after >= m:
        self.hit_milestone[m] = True
        for i in range(N): _acc(i, f"milestone_{int(m*100)}", bonus / N)
```

**`_acc` 是内嵌闭包**（L92-L95）：`if abs(val) > 1e-12` 才记 —— 避免往字典里塞一堆 0 值分量
（否则 `REWARD` 行会被零值淹没）。

**返回值里的契约字段**：
```python
info = {"coverage":..., "new_cells":..., "steps":..., "success":..., "done":...,
        "reward_components": comps}    # ← List[Dict[str,float]]，长度 N
```
**这是全项目唯一能诊断「奖励函数写错」的入口**：训练循环只**累加**这些分量，绝不重算。
只看总奖励曲线，永远看不出「该给的分没给、给错了对象、惩罚过重」。

**和你写法的差别**：你自己大概是
```python
reward = 0
if new_cell: reward += 1
if hit_obstacle: reward -= 0.2
return obs, reward, done, info     # ← 一个数，病因全丢了
```

#### `obstacle_mask` (property) L170
**职责**：每次访问都**重建** `(G,G)` 的 int8 障碍掩膜。
**性能提示**：`step()` 里每个智能体都会访问它 → 单步重建 N 次。
本项目 G=20 可忽略；**如果换到 G=200，这里就是第一个该优化的点**（改成 `__init__` 里建一次）。

#### `coverage()` L176
**职责**：`visited.sum() / free_cells`，返回 `float`。
**⚠️ 注意**：`free_cells = G*G - 障碍数` —— **分母扣掉了障碍**，与你可能习惯的 `G*G` 不同。
改分母会让「覆盖率阈值 0.90」的语义跟着变。

#### `_patch_view(grid, r, c)` L179
**职责**：取以 `(r,c)` 为中心的 `(2p+1)×(2p+1)` 局部视野，**边界用 clip 处理**（不是 padding 0）。
**返回**：展平后的 `((2p+1)²,)`。
**对照**：这就是你 MADQN 里「局部观测」的手写版；这里抽成函数，已访问图和障碍图共用它。

#### `_obs()` L185
**职责**：拼观测。**核心三行**：
```python
vis = self._patch_view(self.visited, r, c)        # ((2p+1)²,)
obs = self._patch_view(obstacle_mask, r, c)       # ((2p+1)²,)
ego = [r/(G-1), c/(W-1), cov, vis.mean()]         # (4,) 自身位置+全局覆盖率+邻域密度
v = concat([vis, obs, ego])                       # (F,) = (54,)
assert v.shape[0] == self.obs_dim                 # ← 自己给自己上维度断言
```
**维度链（务必记住）**：`(F,) × N` → 展平 `(N,F)` → 网络输入；
`obs_dim` 由 `config._derive()` 算出，**环境与网络都读同一个值** —— 这就是不会断链的原因。
**为什么把 `cov` 放进观测**：让策略知道「还剩多少没覆盖」，否则它无从判断该不该去犄角旮旯。

#### `_heading_of(dr, dc, default)` L200
**职责**：把位移方向换算成角度（0/45/…/315）。**当前只用于 `snapshot()` 打印**，
不参与观测与奖励 —— 这是个**预留位**（想加「转向代价」时从这接）。

#### `snapshot()` L206

**返回字段**：网格尺寸 / 智能体数量 / 起始位置 / 目标点位置 / 固定障碍物坐标 / 初始朝向 /
覆盖率阈值 / 步数上限 / 随机种子。
**为什么重要**：**对比两个实验之前，先看这里是否一致** —— 不一致则结果差异可能来自环境而非算法。

#### `render()` L220
**职责**：ASCII 地图（`.` 未访 / `*` 已访 / `#` 障碍 / `T` 目标 / `1..n` 智能体）。

### 5.3 `madqn_agent.py` — `MADQNCTDEAgent`（127 行）

#### `__init__(cfg, obs_dim, n_actions, device)` L28
**三套网络**（这是本文件的核心设计）：
| 网络 | 谁用 | 为什么 |
|---|---|---|
| `online` | learner 学习 + 贪心评估 + 保存 | 唯一的「真身」 |
| `target` | 算 TD 目标 | 稳定训练（就是你的 target net） |
| `rollout` | **后台线程采样专用副本** | 让 actor 与 learner **不共享可变权重**，只做单向同步 |
**代价**：策略有滞后（每轮同步一次）。**收益**：无数据竞争 —— 你如果在主循环里一边采样一边 `learn()`，
其实是隐式共享权重，只是单线程看不出来。

#### `sync_rollout()` L46
**职责**：`online.copy_to(rollout)`。**被调用**：`RolloutActorThread.run()`（持锁调用）。

#### `act(obs, epsilon, net, greedy)` L51
**输入**：`obs (N, F)`；**输出**：`actions (N,)` int64。
**核心逻辑**：
```python
explore  = torch.rand(N) < eps
random_a = torch.randint(0, A, (N,))
greedy_a = self._q(net, obs).argmax(dim=1)
actions  = torch.where(explore, random_a, greedy_a)     # 向量化 ε-greedy
```
**`net` 参数取值**：`"rollout"`（采样）/ `"online"`（贪心评估）/ `"target"`。
**⚠️ 坑**：`act` 默认用 `self.epsilon`（被主线程用 `set_epsilon` 改），
**跨线程读一个 float 是安全的**，但别改成读复杂对象。
**对照**：你的 `if random.random() < eps: a = random else: a = argmax`，
这里是**整批一次算完**（N 个智能体一个 `torch.where`）。

#### `_q(net, obs)` L66
**职责**：按名字取网络做前向，返回 `(B, A)`。`{"online":..., "target":..., "rollout":...}` 字典分发。
**⚠️**：`@torch.no_grad()` —— 推理不开图。

#### `set_epsilon(eps)` L70
**职责**：`clip(eps, 0, 1)` 后写回。**被调用**：主循环每回合（`epsilon_at(cfg, ep)`）。

#### ★ `learn(batch)` L74 —— 唯一的梯度更新点
**输入**：`batch` 来自 `buffer.sample()`，是 dict：`obs (B,F)`、`next_obs (B,F)`、`actions (B,)`、
`rewards (B,)`、`dones (B,)`。
**步骤**：
```python
cur_q = online(obs).gather(1, actions.unsqueeze(1))                 # (B,1)
with torch.no_grad():
    next_a  = online(next_obs).argmax(dim=1, keepdim=True)          # ★ Double DQN：online 选动作
    next_q  = target(next_obs).gather(1, next_a)                    # ★ target 估价值
    td_target = rewards + gamma * next_q * (1 - dones)
td = td_target - cur_q
loss = SmoothL1Loss(cur_q, td_target)                               # Huber，抗离群
optim.zero_grad(); loss.backward()
clip_grad_norm_(online.parameters(), 10.0)                          # ★ 防梯度爆炸
optim.step()
if grad_steps % cfg.MADQN_target_update == 0: online.copy_to(target)  # 硬更新
return {"loss":..., "cur_q":..., "tgt_q":..., "td":...}
```
**`(1 - dones)` 的作用**：终止状态不 bootstrap。
**返回的四个数**都要进日志（`EP` 行的 loss/curQ/td，`TRAIN` 行的 curQ/tgtQ/td）——
它们是**判断 Q 是否发散**的唯一线索（本项目实测 `curQ` 从 0.4 涨到 16，就是发散的信号）。
**被调用**：主循环，**必须持 `weight_lock`**（否则和 actor 的 `sync_rollout` 抢权重）。

#### `save(path, extra)` L103 / `load(path, map_location)` L115
**存的不是一个 `state_dict`，而是一个 payload**：
```python
{"online":..., "target":..., "obs_dim":..., "n_actions":..., "grad_steps":..., "epsilon":..., "extra":{...}}
```
`extra` 里塞了 `ep` / 覆盖率 / **整份 `cfg.to_dict()`** —— 复现实验的凭据。
**`load` 里有一条关键断言**：`payload["obs_dim"] == self.obs_dim`，否则报
「模型观测维度 ≠ 当前环境（环境配置改过？）」—— 这是最常见的「莫名其妙加载失败」的根因。
**⚠️** `torch.load(weights_only=False)`：因为 payload 里有 dict/配置，不是纯张量。

#### `n_params()` L126
**职责**：转发给 `online.n_params()`。**被调用**：训练日志。

### 5.6 `madqn_trainer.py` — 训练设施（437 行，本包最厚的一份）

#### `RolloutActorThread` L45（后台采样线程）

| 成员 | 行 | 职责 |
|---|---|---|
| `__init__` | L46 | 持有 pool / agent / buffer / cfg / `stats_q` / `weight_lock` / `stop_event` / `_sync_request` |
| `request_sync()` | L63 | 置位同步请求（**learner → actor 的唯一通道**） |
| `stop()` | L67 | 置位停止事件 |
| `run()` | L71 | 线程主体 |
| `_pack(info, reward, steps, comps)` | L114 | 把一步的原始统计打成**回合统计字典** |

**`run()` 逐段读**：
```python
obs = pool.reset()                                  # 每个环境一份 (N,F) 的列表
while not stop:
    if _sync_request: with weight_lock: agent.sync_rollout()    # ← 单向同步权重
    flat   = np.stack([o for per_env in obs for o in per_env])  # (E×N, F)
    acts   = agent.act(flat, net="rollout")                     # (E×N,)
    per_env_acts = acts.reshape(E, N)
    nobs, rewards, dones, infos = pool.step([...])              # 真并行
    for k in range(E):
        for i in range(N):
            buffer.push(obs[k][i], per_env_acts[k][i], rewards[k][i], nobs[k][i], dones[k])
            ep_reward[k] += rewards[k][i]
            for name, val in infos[k]["reward_components"][i].items():
                ep_comps[k][name] += val                        # ← 只累加，不重算
        if dones[k]:
            stats_q.put(self._pack(...)); reset accumulator     # 回合结束 → 交回主线程
    obs = nobs
    done_idx = [k for k in range(E) if dones[k]]
    if done_idx: obs[k] = pool.reset_envs(done_idx)             # 局部重置，不打断其他环境
```
**`_pack` 里的两个细节**：
```python
denom = max(1, cfg.agent_num * steps)
"reward": reward / cfg.agent_num,          # 平均到「每智能体」
"components": {k: v/denom for k,v in comps.items()}   # → 「每智能体每步均值」= REWARD 行的口径
```
**`except BaseException` 兜底**：线程里出错**必须**塞进 `stats_q`（`{"_error": repr(e)}`），
否则主线程会永远 `get()` 卡死，而日志一片安静 —— **这是最难查的一类故障**。

#### `theoretical_max_reward(cfg, free_cells, n_targets)` L131
**职责**：算「理论最大单回合奖励」= 覆盖所有空格 + 打到所有目标点 + 拿满里程碑。
**被调用**：`logger.overview()` 那行的「地图平均总奖励」。
**用途**：一眼看出「学到的奖励离上限还差多远」。

#### `GreedyProbe` L138（**本项目的"防坑探针"**）
- `__init__(cfg, agent, seed)` L148：建**固定地图**的环境（`max_steps=final_test_steps`）。
- `run()` L154：贪心跑一回合，返回 `{coverage, success, steps, reward}`。

**为什么必须有它**（**本项目最大的坑**）：训练回合的覆盖率由
**rollout 副本**（滞后权重）在**单回合**上产生，而 `save()` 存的是 **online 权重** ——
**用 A 的表现挑 B**。再叠加「在几百个样本里取 max」的选择偏差。
实测：日志 best 90.5% ↔ 同一模型贪心评估 **53.9%**，差 **36 个点**。
改成按 `GreedyProbe` 选 best 后：best 90.21% ↔ `--mode test` 90.21%，**完全一致**。

#### `_prune(cfg, paths, logger)` L167
**职责**：调 `paths.prune_final_models()` 并**如实打印删了什么**。
**被调用**：两处保存 final 之后（周期保存 + 收尾保存）。

#### `epsilon_at(cfg, ep)` L175
**职责**：两段式探索 —— 前 `MADQN_random_episodes` 轮纯随机（铺回放池），之后线性衰减到 `eps_end`。
**⚠️ 坑**：`episodes` 一改，衰减终点就变（`eps_decay_episodes = 0.8*episodes - random_episodes`）。
**同样的 150 回合：300 回合配置下 ε≈0.42，2000 回合配置下 ε≈0.92** —— 学得快慢完全不同。
这就是规范 §8.4 那个「5000→1000 覆盖率崩掉」事故的机理。

#### `resolve_device(cfg)` L183
**职责**：`auto` → 有 CUDA 用 CUDA，否则 CPU；显式指定则照办。

#### ★ `train_madqn_ctde(cfg, paths, logger)` L189 —— **训练主流程**
按分段读（别想一次读完 156 行）：

| 段 | 行 | 干什么 | 关键调用 |

**⑤ 里最值得注意的三行**：
```python
with weight_lock:                       # ← 学的时候不许 actor 拷权重
    last_metrics = agent.learn(batch)
actor.request_sync()                    # ← 学完通知 actor 更新采样策略
```

## 7. 调用关系总表与欠债清单

### 7.1 两个 dispatch 维度（最容易绕晕的点）

```
test_mode（链路）  ──registry.get_algo()──►  一整套类 + 训练函数
                                              （algos/<algo>/ 六件套）
mode（阶段）       ──MODES[cfg.mode]──────►  train / test / smoke
```
**为什么分两个维度**：链路决定「用哪套算法」，阶段决定「跑到哪一步」。
混在一起（比如 `if mode=="train_madqn"`）会迅速爆炸成组合拳。
`main.py` 文件头的「主入口速查」注释块必须和这两处保持镜像。

### 7.2 关键资源的生命周期（谁建、谁用、谁释放）

| 资源 | 建在 | 谁用 | 释放 |

| `RunPaths` | `main.main` | logger / trainer / eval | — |
| `TrainLogger` | `main.main` | 全线 | `main` 的 `finally` |
| 环境池 | `train_madqn_ctde` ② | actor 线程 | ⑥ `pool.close()` |
