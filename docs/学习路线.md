## 2. 一次 `step()` 的完整数据流（把静态代码串起来）

```
RolloutActorThread（后台线程）                     主线程（learner）
──────────────────────────────────               ────────────────────────────────
obs = pool.reset()                                stats_q.get()  ← 阻塞等一个回合结束
   ↓                                                   ↓
agent.act(flat_obs, net="rollout")                 ε 调度（两段式：先随机、后衰减）
   ↓                                                   ↓
pool.step(per_env_acts)                            buffer.sample(batch) → agent.learn()
   ↓                                                   ↓
env.step() 内：                                     打 EP 行 / TRAIN 行 / REWARD 行
   · 移动（撞障碍=原地+惩罚）                          ↓
   · 覆盖判定 → **当场记录 reward_components**        每 25 回合：GreedyProbe 贪心评估
   · 里程碑 / 停滞判定                                 → 按它存 best（不是按训练回合数字！）
   ↓                                                   ↓
info["reward_components"] → buffer.push()          request_sync() → 线程下次迭代同步权重
   ↓
回合结束 → stats_q.put(该回合统计)
```

**读代码时的两个关键问题**（随时自问）：
1. **这份数据是谁写的、谁读的？**（生产者/消费者一目了然，就不会迷路）
2. **判据和产物对得上吗？**（本项目最大的坑就出在这里）

## 3. 六个动手练习（从易到难）

### 练习 1（5 分钟）：改奖励，看日志分量变化
把 `config.py` 的 `R_repeat` 从 `-0.05` 改成 `-0.5`，跑 30 回合，然后：
```powershell
python main.py --episodes 30 --name exp_repeat
python utils/analyze_training_log.py runs/exp_repeat/train.log
```
看 `[奖励分量 top]` 里 `repeat_penalty` 是不是挤进了前三 —— **这就是「奖励函数诊断」的入口**。

### 练习 2（5 分钟）：换任务规模
```powershell
python main.py --episodes 100 --grid-size 30 --agent-num 3 --name exp_30x30
```
观察：`obs_dim` 变了吗？（没有 —— 观测是**局部** patch，与地图大小无关，这是设计选择）
步数上限够不够？派生量自证块里看。

### 练习 3（20 分钟）：亲手复现那个「best 与 test 不一致」的坑
```powershell
python main.py --episodes 150 --name exp_noprobe --MADQN_eval_interval 0   # 关掉探针
```
（CLI 没有这个参数就直接改 `config.py`。）然后 `--mode test` 对比日志里的 best。
**亲眼看到差 20~40 个点**，比读十遍文档都记得住。

### 练习 4（30 分钟）：加一个奖励分量
在 `madqn_envs.py` 的 `step()` 里加一个 `_acc(i, "explore_bonus", ...)`（比如「首次访问某个象限」），
只改这一个文件 + 在 `config.py` 加一个 `R_explore_bonus`。
然后跑冒烟自检 —— **第⑦项会告诉你诊断脚本还认不认这份日志**。

### 练习 5（1 小时）：加一条新链路
1. 复制整个 `algos/madqn/` → `algos/dqn/`，前缀改 `dqn_`；
2. 把 `agent_num` 固定成 1（单智能体 DQN）；
3. 在 `rlinfra/registry.py` 末尾 `register(AlgoSpec(chain="dqn", ...))` 加一行；
4. `python main.py --test-mode dqn --name exp_dqn`。
**你会发现 `main.py` 一个字都没改** —— 这就是「一算法一包 + 注册表」的收益。

### 练习 6（1 小时）：换网络结构
在 `madqn_networks.py` 加一个 Dueling 版本（value + advantage 两支），
在 `madqn_agent.py` 里换掉 `MADQNQNetwork`。
**改了结构但训练循环一行没动** —— 这就是「网络 ≠ 算法，拆成两个文件」的收益。

## 5. 实验怎么记

```
config.py 的 name  →  runs/<name>/  →  归档时打包这一个目录
```
- **换实验只改 `name` 这一行**，产物天然隔离；
- 对比两个实验 = diff 两个 `runs/<name>/` 目录；
- 日志 `train.log` 是只读证据，别手动改；
- 上集群跑的结果按 `hpc-jobs` 技能的「作业收尾」归档回同名目录。

## 6. FAQ（学习中一定会卡住的几个点）

**Q：为什么要单开一个后台 rollout 线程？**
A：环境 `step` 是纯 Python/numpy，梯度更新是 torch —— 两种负载分开跑 CPU 不空转。
且线程用**独立权重副本**，与 learner 只做单向同步，没有「边学边采样」的隐性竞争。
想旁路它？把 `RolloutActorThread` 换成同步 for 循环即可，接口只有 3 个方法。

**Q：为什么环境是确定性的（起点/障碍/目标都由 seed 决定）？**
A：这样**两次跑出不同结果时，可以直接断言「差异来自算法，不是环境」**。
代价是评估多次跑结果相同 —— 要测泛化加 `--eval-random-maps`。

**Q：为什么要 GreedyProbe 这么麻烦？**
A：训练回合的覆盖率来自**滞后的 rollout 权重**、且是**单回合样本**，
用它选 best = 选「运气好的一回合」。实测差过 **36 个点**。详见 `docs/架构决策.md` §3.3。

**Q：为什么 `parallel` 默认 False？**
A：`mp.Queue` 走命名管道，受限沙箱里会被禁。**单进程降级路径必须永远可用**，
冒烟自检也永远只验它。真实集群上开 `--parallel`。

**Q：为什么产物是 `runs/<name>/` 而不是项目根目录？**
A：代码与产物物理隔离 → 一眼分清、`git status` 干净、清理不用怕误删代码。
（上游 UAV 项目就是被几十个 `reward_*` 目录淹过的，规范的这一条是拿教训换的。）
