# 预注册 · 推/训分离对照实验

> 依据 `UAV-area-search-DQN-opt/docs/DS准备/02_方法论_同预算对照与可辨识性.md` §一
> 🔴 **本文件在实验开跑之前写完并提交**。跑完之后**只许追加结果段，不许改上面任何一个字**。
> 若结果与预注册不符，写进「失败条件」并说明为什么，**不许改判据凑结论**。

## 0. 要回答的唯一问题

B2 已测出：**单卡上 overlap 不划算**（0.933× ± 0.005，t = −22.73）。
机制是"生成与训练排在同一块 GPU、串行化由设备决定"。

⇒ 本实验检验：**把 rollout 与 trainer 分到两块不同的 GPU** 上，overlap 是否转正？
这是单卡结论的**唯一可能例外**，不检验就不能说"overlap 没用"。

## 1. 预注册的四件事（§一 模板）

```
主判据 = overlap 加速比 @ 固定 60 步 × 固定 batch 8 × 固定 max_new_tokens 32
         加速比 ≡ wall(同步,双卡) / wall(overlap,双卡)
         （注意：**两档都在双卡上跑**，唯一变量是"是否并发"，不是"用几张卡"）
阈值   = 落在本仓已观测分布内的值 ⇒ 见 §2 的定量预测 [1.05, 1.25]
预注册的效应量判据 = |t| > 2.2（MDE = 2·SD/√N 一并报出）
对照组 = 同 seed 集 {0,1,2}、同步档；同步数/同 batch/同设备组合；唯一变量 = 是否并发
预注册的失败条件 = 见 §4
```

## 2. 定量预测（**可被推翻**，不是"希望它好"）

用 B2 实测的三段占比（同步档）：`rollout 0.834 / 权重同步 0.025 / 训练 0.141`。

完美分离时每步墙钟 ≈ `max(rollout, train) + 同步`，故

```
预期加速比 ≈ (0.834 + 0.141 + 0.025) / (0.834 + 0.025) ≈ 1.16
```

**预注册点预测 = 1.16；接受区间 = [1.05, 1.25]。**

> 为什么上限不高：rollout 占 83%，它才是长板。分离只能把 14% 的训练藏起来，
> 天花板就是 1/(1−0.141) ≈ 1.16。**这条预测本身就说明"分离有用但收益有限"**。

## 3. 预算口径（§一 第 3 条：按步数不按墙钟）

- 两档都跑 **60 步**，`batch=8`，`prompt_len=8`，`max_new_tokens=32`
- 预热 **6 步**（不计时，排除 CUDA 初始化/cuDNN autotune —— 这是 B2 首轮废数的教训）
- 每档重复 **3 次**取中位数
- 3 个 seed（0/1/2），每个 seed 都跑两档

## 4. 预注册的失败条件（写死，跑完照这个判）

| 观察到 | 判定 |
|---|---|
| 加速比 ≥ 1.05 且 t > 2.2 落在 [1.05,1.25] | ✅ **预测成立**：分离有效，但天花板由 rollout 占比决定 |
| 加速比 ≥ 1.05 但 > 1.25 | ⚠️ **比预测更好**：说明"同步档里还有我没识别出的串行开销"，需归因，不许直接报喜 |
| 加速比 < 1.05（含 t 不显著） | 🔴 **预测被推翻**：分离也没用 ⇒ 单卡结论升级为"overlap 在本工作负载上无收益" |
| 加速比 < 1.0 且 t < −2.2 | 🔴 **反向**：分离后更慢 ⇒ 必须查跨卡权重同步（PCIe）开销 |

**任何一种结果都必须报**，不许只报成立的那种。

## 5. 已知风险（跑之前写下来，免得事后找借口）

1. **平台能否一个作业拿 2 个 MIG 切片未验证**（`-gpgpu "2 mig=1"`）。若被拒 ⇒ 本实验记"未取证"，预注册**保留待做**，不许拿单卡结果冒充。
2. **跨卡权重同步变成 PCIe 传输**（每步 1139.2 KiB）—— 可能吃掉收益，这正是要测的。
3. 模型仍是 `TinyPolicy`(d=128/2 层)：**量结构不量大模型**，结论可迁移性仅限机制层。
4. 若两卡带宽不对称（MIG 切片同卡不同 slice vs 不同物理卡），加速比可能低于预测 —— 需在结果里报"两块卡是否同一物理卡"。

## 6. 结果段（**跑完才填，上面不许改**）

> 作业 `infr-splt-g`（**91796**）· 2026-10-25 20:14–20:15 · 队列 `gpu` · `-gpgpu "2 mig=1"` · 节点 `a800gpu02`
> 命令：`--device cuda:1 --rollout-device cuda:0 --seeds 3 --steps 60 --reps 3 --warmup 6 --batch 8 --max-new-tokens 32`
> 数据：`runs/b_overlap_gpu/{output.91796, overlap_91796.csv, run_91796.log, error.91796}`

### 6.1 数字

| seed | sync 秒（中位） | overlap 秒（中位） | 加速比 |
|---|---|---|---|
| 0 | 1.900 | 2.037 | **0.933×** |
| 1 | 1.858 | 1.967 | **0.945×** |
| 2 | 1.873 | 2.104 | **0.890×** |

```
N = 3 · mean = 0.9225 · SD = 0.0287
MDE(2·SD/√N) = 0.0331
t = (mean − 1)/(SD/√N) = −4.68   ⇒ |t| > 2.2，可区分
```

归因（同步档，seed 均值）：`rollout 0.806 / 权重同步 0.037 / 训练 0.157`。
跨切片权重同步占比从单卡的 **0.025 升到 0.037** —— 搬运确实变贵了，符合预期。

### 6.2 对 §4 判定表的裁决

**加速比 0.9225 < 1.05，且 |t| = 4.68 > 2.2 ⇒ 预注册的点预测 1.16 与接受区间 [1.05, 1.25] 被推翻。**

### 6.3 🔴 但这次**没有真正测到"推/训分离"** —— 按 §5 风险 #4 如实交代

`nvidia-smi -L` 实测：本作业只看到 **2 个 `MIG 1g.10gb` 设备**，而该拓扑下全部 `1g.10gb` 实例都挂在
**同一块物理卡（GPU 2, A800-SXM4-80GB）** 下 ⇒
`cuda:0` 与 `cuda:1` 是**同一物理 GPU 的两个 MIG 切片**，共享同一份 HBM 带宽与同一套显存控制器。
`torch.cuda.get_device_name()` 两者都报 `A800-SXM4-80GB MIG 1g.10gb`，`device_count = 2`。

⇒ **本实验检验的是「同一物理卡的两个 MIG 切片之间能否重叠」，不是「两块物理卡之间能否重叠」。**

因此裁决要**收窄**（不许拿它冒充"分离没用"的证据）：

| 能说的 | 不能说的 |
|---|---|
| 同一 A800 的两个 MIG 1g.10gb 切片之间 overlap 仍更慢（0.9225×，t=−4.68） | ❌ "把 rollout 放到另一块物理卡也没用" |
| 跨切片同步把权重同步占比从 2.5% 抬到 3.7%，收益没能补上这 1.2% | ❌ "推/训分离这条路走不通" |

**真正的物理分卡对照仍未取证**（需调度到两张不同的物理卡；本次平台把 2 个 1g.10gb 切片都放在同一张卡上）。
按 §1 的失败条件表，本实验应记为：**「预测被推翻 + 配置未达预期前提」**，而不是"结论成立"。

### 6.4 事后推测（明确标注是推测，不是结论）

单卡上 rollout 占 83%、训练占 14%。若两块**物理卡**真能并行，理论上限 ≈ 1/(1−0.157) ≈ **1.19**，与预注册的 1.16 同量级。
本实验拿不到，最可能的原因是**MIG 切片之间并不共享 SM 但共享 HBM 带宽**，而两者都在持续打满带宽 ⇒
overlap 反而多付线程/握手开销。要证伪或证实，必须拿到**两张不同物理卡**再跑一次同一命令（代码已就绪）。
