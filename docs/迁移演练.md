# 迁移演练：把「覆盖」换成「追逃」（2026-10-17）

> **一句话**：复制 `algos/madqn/` → 重写**一个** envs 文件 → 登记一行，**2 分 18 秒**后冒烟通过；
> 训练 / 评测 / 观测契约三条链路零改动接住新域。
> 代价不在基座，而在**领域知识**（奖励设计 + 选优判据）—— 这条结论只有真做一次才拿得到。

**这份文档存在的理由**：README 的「迁移账单」里，「换任务只改一个文件」原来是**设计主张**，没有实测。
本演练把它变成可复查的账单；同时暴露了 4 个真实设计缺陷（§5），这些缺陷**不是**靠读代码能发现的。

## 4. 结果

### 4.1 域本身可解吗？先把「学不会」和「不可解」分开

`python scripts/probe_pursuit.py --maps 20`（无学习：每步朝目标走曼哈顿最近方向）：

| 逃逸步频 | 捕获 | 平均步数 | 平均搜查 |
|---|---|---|---|
| `PURSUIT_evader_period=2`（config 默认） | **20/20 = 100%** | 7.8 | 4.34% |
| `PURSUIT_evader_period=1` | **3/20 = 15%** | 170.2 | 8.97% |

⇒ ① 域可解；② **逃逸步频是决定难度的旋钮**（100% ↔ 15%），一条命令就能量出来 —— 这正是"换域要调参数"的成本所在。

### 4.2 学到的策略（`pursuit_drill`，400 回合，本地 CPU）

| 指标 | 数值 | 出处 |
|---|---|---|
| 训练墙钟 | 348.4 s / 400 回合 | `runs/pursuit_drill/train.log` 收尾行 |
| 训练期选出的 best（按**搜查覆盖**） | 57.22% @ ep100 | 同上 |
| 贪心探针（固定图 seed=0） | 16 次里 **15 次捕获**，后期 8 步即捕获 | 训练日志 `贪心评估 ep…` 行 |
| **20 图评测** | 搜查覆盖 **28.30% ± 15.87pp** · **捕获率 70%** · 平均 **96.9 步** | `--mode test --eval-runs 20` 汇总行 |
| 对照：直线追击启发式 | **100%** 捕获 / **7.8 步** | §4.1 |

⇒ 与覆盖任务同一结论：**学到的策略不如一个无学习启发式**（70% vs 100%，且慢 12 倍）。
但这次多了一条更强的证据：训练日志里 ep400 的贪心探针**8 步就捕获**，而保存下来的 `best` 是"覆盖最高"的那个 ——
**选优判据写死成 coverage**（`pursuit_trainer.py` 的 `GreedyProbe`），换域后它就选错了模型（缺陷 #4）。

### 4.3 观测契约：零改动接住

```powershell

# ✅ pursuit_drill：2696 条指标 / 2 个事件 → runs/obs/pursuit_drill
#    指标名（18）：coverage, cur_q, ep_reward, epsilon, loss, reward/approach, reward/capture,

```

`utils/log_to_metrics.py` **一行未改**就吃下了新域，连新奖励分量 `reward/approach`、`reward/capture` 都自动成了指标名
（因为分量名是随 `reward_components` 契约传的，不是写死的字段）。观测平台侧同样零改动。

## 5. 演练真正买到的东西：4 个被撞出来的设计缺陷

| # | 缺陷 | 症状（如果不改会怎样） | 处置 |
|---|---|---|---|
| 1 | **注册表只登记 train，没登记 eval** | `--mode test --test-mode pursuit` 会**静默地**跑 madqn 的 `evaluate_madqn`：读 `pursuit_best.pth`、按覆盖任务口径解读，不报错、数字全是错的 | ✅ 已修：`AlgoSpec.eval_fn` + `main.py` 走注册表（+3 行） |
| 2 | **参数前缀 `MADQN_*` 被两条链路共用** | 追逃环境要读 `cfg.MADQN_patch`、`cfg.MADQN_buffer_size`……名字宣布了归属，实际是"模型族共享参数" | ✅ **已修**（2026-10-17）：13 个共用参数 `MADQN_*` → `COMMON_*`（12 文件 / 168 行机械改名）；**取值逐字不变**（`obs_dim=54`、`eps_decay=230`、`to_dict()` 53 键零值差）⇒ 历史 run 仍可比。映射表见 `docs/库边界.md` §7。⚠️ 用旧名写的外部脚本会**响亮地** AttributeError —— 刻意不保留别名，避免"两名并存"的新债 |
| 3 | **评测汇总行的「成功判据 0.75」对追逃无意义** | 覆盖任务的 `env.threshold` 被评测层统一覆盖；追逃的 `threshold` 只是里程碑，成功判据是"捕获" ⇒ 日志里那行"成功判据 0.75"是**误导性元数据** | ✅ **已修**：成功判据改为**链私有** `success_rule`（`覆盖率 ≥ 0.75` / `捕获（曼哈顿 ≤ 0）`），进日志**和 `eval.json`**；顺带补上「本地 `--mode test` 也写 eval.json」（此前只有高算 `scripts/eval_runs.sh` 写，AGENTS 里那句话对本地是假的） |
| 4 | **选优判据写死 coverage** | 训练期保存的 `best` 是"搜查最多"的模型，不是"最能抓到"的模型（ep400 贪心 8 步捕获，却因覆盖低而不被选） | ✅ **已修**：`probe_key()` 按链路压成元组 —— 覆盖域 `(coverage,)`（与旧行为逐字等价）、追逃域 `(是否捕获, −步数, coverage)`；配置 `MADQN_best_metric` / `PURSUIT_best_metric`。验收见 §5.1 |

> **这 4 条的性质**：都不是"代码有 bug"，而是**抽象漏了一层** ——
> 只有真的把域换掉，才会发现"注册表少一个字段""评测少一个抽象""选优少一个配置"。
> 这也是本次演练对 infra 的直接产出（比多跑几个实验有用）。

### 5.1 修复验收：两种选优判据差 +25pp（`scripts/compare_ckpt_selection.py`）

同一批 6 个存档（`pursuit_best` + `final_1…5`）在**同一 20 张图**上重评，再分别按两种判据选优：

| checkpoint | 捕获率 | 平均步数 | 搜查覆盖 |
|---|---|---|---|
| `pursuit_best.pth`（按 coverage 选出） | 70% | 96.9 | 28.30% ± 15.87 |
| `pursuit_final_1` | 70% | 96.9 | 28.30% ± 15.87 |
| `pursuit_final_2` | 65% | 103.6 | **29.92%** ± 18.12（覆盖最高） |
| `pursuit_final_3` | 75% | 92.1 | 26.30% ± 18.25 |
| **`pursuit_final_4` / `5`** | **90%** | **63.5** | 18.84% ± 16.69 |

- 按 **coverage** 选 → `final_2`（捕获 65%）
- 按 **capture_steps** 选 → `final_4`（捕获 **90%**，63.5 步）
- ⇒ 两种判据选出的**不是同一个模型，捕获率差 +25pp** ⇒ 预注册判据（≥10pp）成立，缺陷 #4 有实际后果。

**口径收窄**：这是在**同一个 400 回合 run 的 6 个存档**上做的**事后重选**，不是重训 ——
只能说"存档里本来就存在一个 90% 的模型，旧判据没选中它"，**不能**说"训练过程被改好了"。
另外 `final_4` 与 `final_5` 数字逐字相同 ⇒ 300→400 回合策略已饱和（与本项目一贯结论一致）。

## 6. 口径收窄与诚实短板

- **只演练了一次**，而且是**同域内的最小切换**：仍是 2 智能体 · 20×20 栅格 · 9 动作 · 确定性环境；目标**全局可见**（无部分可观性）。
  ⇒ 不能据此宣称"任意任务都能只改一个文件"。可信的说法是：**同一"栅格多智能体"家族换域，改动面 = 1 个 envs 文件 + 1 行注册**。
- **基线不对等**：直线追击用的是全局目标位置，学到的策略看的是观测里的 Δ 位置（同样是全局，这次算对等）；但启发式**无探索惩罚**，且不做"搜查"这一目标 —— 两者优化目标不同，只能比"能不能抓到/多快抓到"。
- **单 seed**：`pursuit_drill` 只训了 1 个 seed；70% 捕获率没有置信区间。
- **墙钟依赖机器状态**：348.4 s / 400 回合是本次实测，CPU 有其它负载。
- **`runs/` 不进 git**：上表证据路径（`runs/pursuit_drill/…`）只在本机；可复现的部分是**命令**，不是产物。

## 7. 复现（约 7 分钟，全程本机 CPU）

```powershell

# 然后：(已提交的 algos/pursuit/pursuit_envs.py 就是重写结果；自己重做时按 §2 手改这一个文件)

python main.py --test-mode pursuit --name pursuit_drill --episodes 400 --print-interval 20
python main.py --mode test --test-mode pursuit --name pursuit_drill --eval-runs 20   # 本地也会落 eval.json

python scripts/compare_ckpt_selection.py --run pursuit_drill --maps 20               # 选优判据验收（§5.1）
```
